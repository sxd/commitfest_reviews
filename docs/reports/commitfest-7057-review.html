Overview

The patch rewrites a single paragraph in doc/src/sgml/ref/values.sgml (lines 201–207) that follows the FROM (VALUES ...) AS t(...) example block. The OLD text stated "an AS clause is required when VALUES is used in a FROM clause" — this was inaccurate. The NEW text states "it's not necessary to have an AS clause specifying names for each column, but it's good practice to do so."

The technical correction is accurate: in src/backend/parser/gram.y:14437 the production table_ref: select_with_parens opt_alias_clause makes the alias optional for any subquery in FROM (including VALUES), and src/backend/parser/parse_relation.c:2264–2308 (addRangeTableEntryForValues) defaults refname to *VALUES* and fills column names as column1, column2, … when no alias is supplied. The contributor notes this has not been the case since PostgreSQL 16 (commit bcedd8f).

F2

— Wording less precise on partial column alias lists (NIT, docs, verified)

  • Location: doc/src/sgml/ref/values.sgml:202
  • Mechanism: The NEW wording "not necessary to have an AS clause specifying names for each column" is less precise than HEAD's "not required that the AS clause specify names for all the columns". The new phrasing can be read as conflating "having an AS clause at all" with "specifying names for each column", obscuring that a PARTIAL column alias list is accepted.
  • Failure: Documentation precision regression: the partial-alias-list capability is no longer explicitly hinted. The parser accepts partial alias lists: parse_relation.c:2295-2303 loops while (numaliases < numcolumns) filling unspecified columns with columnN defaults, and errors only when numcolumns < numaliases.
  • Verification: inspection of working-tree SGML lines 200–206 vs HEAD lines 200–205; parser behavior confirmed by reading src/backend/parser/parse_relation.c:2290-2303 and queries.sgml:663-664.
  • Repair intent: Reword to explicitly state both that an AS clause is not required and that the AS clause need not name every column (partial alias lists accepted). Suggested: "If VALUES is used in a FROM clause, it is not necessary to have an AS clause, nor is it necessary that the AS clause specify names for all the columns, but it's good practice to do so."
