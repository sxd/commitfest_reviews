Patch summary

A pure regression-test patch that adds edge-case, error-path, and encoder-branch coverage for the phonetic encoders in contrib/fuzzystrmatch:

  • soundex: leading non-alphabetic skip (-hello, 3M, !@#).
  • metaphone: empty/short input; the three distinct ereport error paths

(argument > 255 bytes, output > 255 bytes, output ≤ 0); two large tabular cases exercising first-letter and rest-of-word transformation rules.

  • dmetaphone / dmetaphone_alt: empty input; a 51-name common-case table

(canonical DoubleMetaphone reference corpus); a 29-name "rarer branches" table (MC+CH, CC+IA/E/H/consonant, CI Slavic, DG+consonant, GH after consonant / initial, GN internal, GLI, GER, SCH+G, JOSE, J internal/final, SH+HOLM, SIAN, SCH+consonant/OO, SC+I/consonant, TION, W+H); a long-input case (repeat('schwarzenegger', 20)); a buffer-growth regression (agliagliaglia).

  • daitch_mokotoff: no-encodable-character inputs ('', '123') and a

reserved-internal-character input ('a[b').

No C source, no Makefile/meson.build, no *.control, no extension-definition SQL, and no catalog/contract changes. catversion is correctly not bumped.

Findings

PR-1

— NIT — maintainability — contrib/fuzzystrmatch/sql/fuzzystrmatch.sql:183

Mechanism: The new daitch_mokotoff('a[b') test pins behaviour where literal [, \, ] are silently treated as non-encodable because they are reserved for internal ISO-8859 → ASCII conversion (daitch_mokotoff.c:411-414, if (c >= '[' && c <= ']') return na;). The existing comment names the mechanism but not the pinned contract.

Failure: A future refactor could legitimately reject literal reserved characters via ereport(ERROR) instead of silently skipping them, breaking this oracle without warning; the pinned contract is not stated.

Verification: Source inspection confirms the return na branch for reserved [,\,]; SELECT daitch_mokotoff('a[b') returns {070000} (only a encodes, the literal [ is silently non-encodable), matching the pinned oracle at expected/fuzzystrmatch.out:518-524.

Repair intent: Tighten the comment to state the pinned contract in both the .sql file and the echoed copy in expected/fuzzystrmatch.out.

PR-3

— NIT — tests — contrib/fuzzystrmatch/sql/fuzzystrmatch.sql:28

Mechanism: metaphone('', 4) and metaphone('-', 10) are success cases (empty output) placed under the -- Edge cases and errors heading that also contains the three ERROR: rows (argument > 255 bytes, output > 255 bytes, output ≤ 0). Success and error rows are interleaved under one banner.

Failure: Mild categorisation drift: empty-result success cases and ereport error paths share a single heading.

Verification: Inspection of sql/fuzzystrmatch.sql:28-34 and expected/fuzzystrmatch.out:95-114 confirms two (1 row) empty-result blocks immediately followed by three ERROR: blocks, all under the single -- Edge cases and errors comment.

Repair intent: Split into -- Edge cases (empty/non-alphabetic success cases) and -- Errors (the three ereport error paths) in both the .sql file and the echoed copy in expected/fuzzystrmatch.out.
