Review: Whole-row fixes for DROP COLUMN, SET COLUMN DATA TYPE

CommitFest 61, Patch 6055 | Author: Jian He | Reviewer: pg-review-harness (glm-5.2:cloud) Thread: https://postgr.es/m/CACJufxGA6KVQy7DbHGLVw9s9KKmpGyZt5ME6C7kEfjDpr2wZCw@mail.gmail.com

Scope

The patch modifies ATExecDropColumn() in src/backend/commands/tablecmds.c to also drop CHECK constraints and indexes that contain whole-row Var references (attnum 0) when any column is dropped. The existing dependency machinery already drops objects that directly reference the dropped column; the patch closes a gap where objects referencing the whole row (e.g., CHECK (t IS NOT NULL), CREATE INDEX ON t ((t)) WHERE t IS NOT NULL) were orphaned with a stale rowtype after DROP COLUMN.

Changed files: src/backend/commands/tablecmds.c (+122 lines), src/test/regress/expected/constraints.out (+17), src/test/regress/expected/indexing.out (+25), src/test/regress/sql/constraints.sql (+11), src/test/regress/sql/indexing.sql (+9)

Changed function: ATExecDropColumn (lines 9425-9738)

Verdict: needs-review

No BLOCKERs. Three MAJOR findings (2 correctness, 1 test). Live thread objection from Matthias van de Meent (2026-08-05) regarding the scanning approach. Findings

MAJ-1

— MAJOR — Correctness — else if skips indexprs whole-row check when indpred is non-null

Location: src/backend/commands/tablecmds.c:9605

Mechanism: An index can have both indpred (partial-index predicate) AND indexprs (expression columns) non-null simultaneously (e.g., CREATE INDEX ON t ((t)) WHERE a > 0). The patch's else if at line 9605 means that when indpred is non-null, indexprs is never examined. If the whole-row reference is in the expression list but not the predicate, the index will NOT be dropped.

Failure: After ALTER TABLE t DROP COLUMN <col> where t has CREATE INDEX ON t ((t)) WHERE a > 0, the expression index ((t)) survives with a now-mismatched whole-row type, causing latent data corruption.

Verification: Confirmed by manual test. Before fix: index survives. After applying repair (else-if → if): index correctly dropped.

Repair: Change else if to independent if. Add bms_free, ReleaseSysCache, and continue after finding whole-row in indpred to avoid duplicate adds. Patch SHA-256: 938f4caf325cad65e37809e86d77081b4a8779a7833b6bed86c6984f1cbde7a2. Validation: passed (apply-check, diff-check, compile, targeted-test).

MAJ-2

— MAJOR — Correctness — Title claims SET DATA TYPE but diff only touches DROP COLUMN

Location: src/backend/commands/tablecmds.c:15395 (ATExecAlterColumnType, unmodified)

Mechanism: The patch title and v14 commit message claim to fix both DROP COLUMN and SET COLUMN DATA TYPE, but the frozen diff only modifies ATExecDropColumn. ATExecAlterColumnType is not modified. The SET DATA TYPE whole-row problem remains unfixed.

Failure: ALTER TABLE ALTER COLUMN SET DATA TYPE with a whole-row-referenced CHECK constraint silently corrupts the constraint.

Verification: Static analysis confirms no changes to ATExecAlterColumnType in the diff.

Repair: Add a whole-row check constraint error-out at the beginning of ATExecAlterColumnType. Patch SHA-256: 3aad5b13c2fd59036f97f28e977aed93d3a58bc5ac32088fc97880fe29de85a3. Validation: not-run (proposal for author).
