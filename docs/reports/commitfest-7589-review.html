Target: COPY TO with row-level security (RLS) builds an explicit target list from attnums (which excludes dropped and generated columns) instead of SELECT *. Verdict: ready-for-committer · Blockers: 0 (0 verified / 0 unverified) Scope identity (diff SHA, uncommitted worktree): 4165d2fee08cb89394d0fafc4f539eb7a860b2d5 Base = HEAD: 4244818f8add2a8ffbc89fcaa03e2871cf270ec0 (uncommitted work on a read-only worktree)

Patch summary

In DoCopy() (src/backend/commands/copy.c), the RLS-enabled branch (check_enable_rls(...) == RLS_ENABLED) previously built the query-based COPY as SELECT * FROM ONLY <rel>. * expands to all non-dropped columns including stored generated columns, whereas the non-RLS COPY TO path (DoCopyTo → CopyGetAttnums(tupDesc, rel, NIL)) excludes both dropped and generated columns (copy.c:1087-1094). The two paths were therefore inconsistent: COPY rel TO STDOUT exported generated columns only when RLS was active for the calling role, contradicting the documented behavior ("all columns of the table except generated columns will be copied") and producing output that could not be copied back in.

The patch replaces the A_Star ColumnRef with a loop over the already-computed attnums, building one named ColumnRef/ResTarget per non-dropped, non-generated column via TupleDescAttr(tupDesc, attno-1)->attname (pstrdup'd). This aligns the RLS COPY TO projection with the non-RLS COPY TO projection. A self-contained regression test (copy_rel_to_gen) is added to src/test/regress/sql/rowsecurity.sql with matching expected output.

Changed files: src/backend/commands/copy.c (DoCopy), src/test/regress/sql/rowsecurity.sql, src/test/regress/expected/rowsecurity.out. Changed function: DoCopy. No catalog change, no new OID, no catversion bump, no pg_dump impact.

Security section

No security regression. The patch reduces information exposure: previously an RLS-subject role could COPY <rel> TO and observe stored generated-column values via SELECT *; after the patch those columns are excluded, matching the non-RLS path. Generated columns are deterministic functions of base columns the same role can already read, so hiding them reduces exposure rather than creating a leak. RLS policy evaluation itself is unchanged (policies may still reference generated columns in USING). selectedCols permissions bitmap is consistent with the non-RLS path. Dropped-column resurrection is impossible (CopyGetAttnums skips attisdropped, parity with *).
