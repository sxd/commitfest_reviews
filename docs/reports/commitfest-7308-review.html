CommitFest 7308 Review: VACUUM Truncation Threshold Adjustment

Summary

Target: CommitFest 7308: VACUUM truncation threshold adjustment (should_attempt_truncation) Base/Head (full HEAD): 926627bf9021137af66ac3bf21d1595af64ec66b Scope identity: diff-0ce64c3fe313dc85ee4aadd4397a2196d436ac8fc1bb796f93e3c795bdcbff21 Verdict: needs-review Blocker counts: verified=0, unverified=0 Changed file: src/backend/access/heap/vacuumlazy.c (staged, uncommitted; 3 insertions, 5 deletions) Model: glm-5.2:cloud (explicit user override)

Patch under review

The staged diff lowers REL_TRUNCATE_MINIMUM from 1000 to 2 and REL_TRUNCATE_FRACTION from 16 to 32, and rewrites the should_attempt_truncation predicate from an OR of two independent thresholds (possibly_freeable >= MINIMUM || possibly_freeable >= rel_pages/FRACTION, guarded by possibly_freeable > 0) to a single additive threshold (possibly_freeable >= rel_pages/REL_TRUNCATE_FRACTION + REL_TRUNCATE_MINIMUM). The intent (per the pgsql-hackers thread) is to reduce unnecessary AccessExclusiveLock truncation attempts on relations where the freeable tail is small relative to the relation size.

diff
-#define REL_TRUNCATE_MINIMUM	1000
-#define REL_TRUNCATE_FRACTION	16
+#define REL_TRUNCATE_MINIMUM	2
+#define REL_TRUNCATE_FRACTION	32
...
-	if (possibly_freeable > 0 &&
-		(possibly_freeable >= REL_TRUNCATE_MINIMUM ||
-		 possibly_freeable >= vacrel->rel_pages / REL_TRUNCATE_FRACTION))
+	if (possibly_freeable >= vacrel->rel_pages / REL_TRUNCATE_FRACTION + REL_TRUNCATE_MINIMUM)
