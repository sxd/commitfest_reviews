CommitFest 7578 — Periodically refresh database frozen IDs during autovacuum

Scope

Uncommitted CommitFest patch staged on HEAD 31878ccc2cd5 (== origin/master). The patch adds a periodic, throttled refresh of pg_database.datfrozenxid between autovacuum tables, a nowait mode for vac_update_datfrozenxid(), a new ConditionalLockDatabaseFrozenIds() helper, and a new per-database pgstat field last_frozenxid_update (with PGSTAT_FILE_FORMAT_ID bumped from 0x01A5BCBD to 0x01A5BCBE).

Changed files:

  • src/backend/commands/vacuum.c — vac_update_datfrozenxid(bool nowait), now publishes last_frozenxid_update.
  • src/backend/postmaster/autovacuum.c — periodic vac_update_datfrozenxid(true) between tables, throttle helper autovacuum_datfrozenxid_update_due().
  • src/backend/storage/lmgr/lmgr.c — new ConditionalLockDatabaseFrozenIds().
  • src/backend/utils/activity/pgstat_database.c — new pgstat_report_frozenxid_update(); flush assertion.
  • src/include/commands/vacuum.h, src/include/pgstat.h, src/include/storage/lmgr.h — declarations.

Verification Summary

Static review found no correctness, security, memory-safety, or catalog-version defects: the nowait lock-acquisition path returns before publishing a timestamp only when the lock is unavailable (so the throttle correctly retries on the next table); the bogus-data early return still precedes pgstat_report_frozenxid_update() so a corrupt database keeps retrying; the pgstat field is written under the shared-entry lock while the frozen-ID lock is held, with no inverse lock ordering observed; the PGSTAT_FILE_FORMAT_ID bump is the correct response to the on-disk PgStat_StatDBEntry layout change; and the throttle correctly handles a backward clock (last_update > now) and a missing stats entry.
