Change Summary

The patch replaces llvm::MemoryBuffer::getFile(path) (the C++ overload whose default std::optional<Align> argument is instantiated at the call site and SIGSEGVs under a GCC-13/distro-LLVM-17 compiler mismatch) with the C-API call LLVMCreateMemoryBufferWithContentsOfFile, matching the established pattern in load_module() (same file, line 494) and llvm_create_types() (src/backend/jit/llvm/llvmjit.c:1005). The buffer is materialised into a llvm::MemoryBufferRef via *llvm::unwrap(buf), and LLVMDisposeMemoryBuffer(buf) is invoked on both the success path and the elog(FATAL) path. A std::string pathstr(path) is introduced because the C API requires a NUL-terminated const char *.
