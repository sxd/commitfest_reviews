The original bug (pgsql-hackers thread 623416, Jian He, 2025-09-27): a single ALTER TABLE combining ALTER COLUMN ... SET DATA TYPE and ALTER COLUMN ... SET EXPRESSION on the same generated column errors with cache lookup failed for constraint because ATRewriteCatalogs calls ATPostAlterTypeCleanup twice for the same relation and the second call re-processes already-dropped constraint OIDs.

Verdict

waiting-on-author — one verified BLOCKER.

The worktree contains the v1 dedup-by-relid approach, which David Rowley rejected on 2025-09-28 and the author replaced with v6 (reset the changed_* lists to NIL at the end of ATPostAlterTypeCleanup) on 2026-08-02. The v6 approach was confirmed correct by Evan Li on 2026-08-03. The worktree must be updated to v6 before this patch can proceed.

Findings

SEC-1

— BLOCKER — correctness — src/backend/commands/tablecmds.c:5457

Mechanism: The dedup-by-relid guard skips ATPostAlterTypeCleanup for the AT_PASS_SET_EXPRESSION pass when AT_PASS_ALTER_TYPE already ran cleanup for the same relation. This leaves constraints/indexes registered *only* by RememberWholeRowDependentForRebuilding (and per-column dependents of the expression-changed column) un-rebuilt.

Why this is wrong: ATPostAlterTypeCleanup processes tab->changedConstraintOids, changedIndexOids, changedStatisticsOids, replicaIdentityIndex, and clusterOnIndex. These lists are *accumulated across passes*:

  1. During AT_PASS_ALTER_TYPE, ATExecAlterColumnType registers

constraints/indexes dependent on the type-changed column.

  1. ATPostAlterTypeCleanup runs, drops those objects via

performMultipleDeletions, and queues re-add commands. Under v1 the relid is recorded.

  1. During AT_PASS_SET_EXPRESSION, ATExecSetExpression calls

RememberAllDependentForRebuilding and RememberWholeRowDependentForRebuilding (tablecmds.c:8836/:8843), registering *additional* constraints/indexes dependent on the expression-changed column — including whole-row CHECK constraints (pg_depend refobjsubid = 0) that the per-column pg_depend scan in step 1 cannot find (RememberWholeRowDependentForRebuilding has Assert(subtype == AT_SetExpression) and is called *only* from ATExecSetExpression).

  1. Under v1, ATPostAlterTypeCleanup is skipped because relid is already

in relids. The newly-registered objects from step 3 are never dropped, never reparsed, and never queued for re-addition.

Empirical reproduction (coordinator-executed, disposable build):

Cross-column whole-row counter-example against the v1 worktree patch:

sql
CREATE TABLE gtest_blocker3 (a int, z int, b int GENERATED ALWAYS AS (a*2) STORED, c text);
ALTER TABLE gtest_blocker3 ADD CONSTRAINT cc_col CHECK (z > 0);       -- per-column dep on z
ALTER TABLE gtest_blocker3 ADD CONSTRAINT cc_wr CHECK (gtest_blocker3 IS NOT NULL); -- whole-row (refobjsubid=0)
ALTER TABLE gtest_blocker3 ALTER COLUMN z SET DATA TYPE bigint, ALTER COLUMN b SET EXPRESSION AS (a*3);

Under v1: cc_col OID changed 17919 → 17922 (rebuilt by ALTER_TYPE pass), but cc_wr OID stayed 17920 → 17920 (NOT rebuilt — the SET_EXPRESSION cleanup was skipped). pg_depend for cc_wr has refobjsubid = 0, so only RememberWholeRowDependentForRebuilding (SET_EXPRESSION pass) registers it.

David Rowley's per-column counter-example (thread 623416, 2025-09-28) shows the same defect for a non-whole-row constraint on the generated column when only a *different* column's type is altered: cc check (b > 0) is not recreated.

Security relevance: CHECK constraints may silently fail to be rebuilt against the new column type/expression; replica identity and CLUSTER index markings may be lost, affecting logical replication correctness. Privilege neutral (any table owner can trigger it); the impact is catalog consistency and constraint enforcement. CWE-863 (incorrect enforcement) / catalog inconsistency.

Verification status: verified (by reproduction + pgsql-hackers thread corroboration).

Repair (v6): Revert the dedup-by-relid guard and instead reset the changed_* lists to NIL/NULL at the end of ATPostAlterTypeCleanup, after performMultipleDeletions + free_object_addresses. This allows the second cleanup call to process only objects registered by the SET_EXPRESSION pass.
