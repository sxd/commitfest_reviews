Review Report — CommitFest 6960: COALESCE Selectivity Estimation

Patch: COALESCE selectivity estimation in src/backend/utils/adt/selfuncs.c (+434 / -30 lines) Author: Egor Savelev (Tantor Labs) — pgsql-hackers thread 650175 Verdict: needs-review Blockers: 0 verified, 0 unverified

Executive Summary

The patch adds COALESCE selectivity estimation to selfuncs.c, decomposing COALESCE(...) = ... predicates and hash keys into reach-probability-weighted sums of per-branch selectivities. The approach is architecturally sound and the common cases (COALESCE of Vars, COALESCE with a trailing const) are estimated well. The build is clean with --enable-cassert.

Two MAJOR correctness defects are verified and must be fixed before commit:

  1. PR-1 (neqsel <> bypass): COALESCE(a,1) <> 5 returns the un-negated eq estimate (~10187 rows) instead of the negated estimate (~90000 rows) — off by ~9x. This is corroborated live in pgsql-hackers thread 650175 (Ilya Evdokimov, 2026-08-17). Repair validated: COALESCE(a,1) <> 5 → 89703 rows after fix.
  1. PR-3 (is_eqjoin dispatch broken under DirectFunctionCall): try_coalesce_eq detects eqjoin via fcinfo->flinfo->fn_oid, but DirectFunctionCall*Coll sets flinfo=NULL, so nested-COALESCE join sub-pairs are dispatched to eqsel instead of eqjoinsel. Edge case reproduced (5000 → 1000 rows after fix). Common cases bail harmlessly.

One MAJOR process gap (PR-4): no regression tests added. A proposal-only test suite (13 scenarios) was produced and validated.

Version discrepancy: the frozen worktree is v3 (2026-08-07), not the latest v4 (2026-08-17). v4 moved the leading-Const check before the loop and changed the early-stop threshold to a product — neither change is in the frozen diff.

Verification Summary

PR-1

— neqsel (<>) bypasses negation — VERIFIED (repro)

Runtime evidence (live cluster, coverage-instrumented build, port 55555):

  • a <> 5 → rows=90067 (correct, ~90%)
  • COALESCE(a, 1) <> 5 → rows=10187 (WRONG — returns the eq estimate, not the negated estimate)
  • a = 5 → rows=9933; COALESCE(a, 1) = 5 → rows=9933 (correct)

The <> path returns the eq selectivity because try_coalesce_eq runs before eqsel_internal's negate handling (1.0 - eq_sel - nullfrac). Corroborates pgsql-hackers thread 650175 msg #9 (Ilya Evdokimov, 2026-08-17): 10260 vs 90057.

Repair validated (port 55556, repaired cluster): COALESCE(a,1) <> 5 → rows=89703 (was 10187). The fix threads a bool negate flag into try_coalesce_eq and applies 1.0 - acc_selec - coal_nullfrac for the restriction negation case.

PR-3

— is_eqjoin detection broken under DirectFunctionCall — VERIFIED (repro)

DirectFunctionCall4Coll/5Coll set fcinfo->flinfo = NULL (fmgr.c:867,894). The inner recursive try_coalesce_eq sees is_eqjoin=false and dispatches nested-COALESCE join sub-pairs via eqsel instead of eqjoinsel.

  • Common case bails harmlessly: for COALESCE(Var,Var)=COALESCE(Var,Var), the inner match_coalesce_join_side returns false (plain Var is not CoalesceExpr), so normal eqjoinsel runs. Live: rows=1250 (correct).
  • Edge case reproduced: with expressional indexes on nested COALESCE, COALESCE(COALESCE(a,b),c)=COALESCE(COALESCE(x,y),z) → rows=5000 (default, wrong dispatch) vs rows=1000 (repaired, correct join estimate).

Repair: replace flinfo->fn_oid check with is_eqjoin = (fcinfo->nargs == 5). nargs is preserved under DirectFunctionCall. Validated: common join unchanged, nested-COALESCE-join fixed.

PR-4

— No tests added — VERIFIED (diff-check)

git diff HEAD --name-only shows only selfuncs.c; no test files. A proposal-only test suite (selectivity_coalesce.sql, 13 scenarios) was produced by pg-test-author, apply-checked clean, and loaded against the running cluster with all scenarios producing deterministic output.
