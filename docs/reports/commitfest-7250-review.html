Findings

BLOCKER-A — glist_delete / glist_delete_thoroughly dclist arms reference non-existent functions

  • Location: src/include/lib/ilist.h:1187, 1191
  • Class: correctness
  • Mechanism: The dclist associations of glist_delete and glist_delete_thoroughly call dclist_delete(head, node) and dclist_delete_thoroughly(head, node). These symbols do not exist anywhere in the tree (confirmed via grep across src/). dclist only provides dclist_delete_from(head, node) (ilist.h:763, count--) and dclist_delete_from_thoroughly(head, node) (ilist.h:776, count--).
  • Failure: Any translation unit instantiating glist_delete or glist_delete_thoroughly against a dclist_head * fails to compile with implicit-declaration errors. The patch does not compile for half its intended type set.
  • Verification: verified (compile) — gcc -std=c11 -fsyntax-only on a stubbed TU produced ilist.h:1187:26: error: implicit declaration of function 'dclist_delete' and ilist.h:1191:26: error: implicit declaration of function 'dclist_delete_thoroughly' (4 errors total in baseline transcript).
  • Thread disposition: new (not raised by any thread participant; Tristan Partin falsely claimed name correctness).
  • Repair: Route the dclist arms to dclist_delete_from / dclist_delete_from_thoroughly using the function-form _Generic with head-accepting wrappers for the dlist branch. Repair validation: passed (combined patch, apply-check + diff-check + compile + repro).

BLOCKER-B — glist_foreach uses first real node as end sentinel, visits head sentinel as element, skips first node, asserts on empty

  • Location: src/include/lib/ilist.h:1246-1256, 1231-1242
  • Class: correctness
  • Mechanism: glist_foreach_init sets iter.end = glist_head_node(lhead) (the first REAL node, Assert(!dlist_is_empty) / Assert(count>0)) instead of &(lhead)->head (the head SENTINEL) as canonical dlist_foreach (ilist.h:626) does.
  • Failure: glist_foreach over [a,b,c] visits b, c, then the head sentinel as a user node (OOB dlist_container deref), and skips a. On an empty list it asserts and aborts instead of iterating zero times. Every existing dlist_foreach caller relies on zero-iteration-on-empty.
  • Verification: verified (repro) — runtime trace: visit 0: v=1, visit 1: v=2, visit 2: cur=<HEAD SENTINEL> [BUG], v=0 skipped; canonical dlist_foreach produced v=0,1,2. Empty-list hits Assert(!dlist_is_empty) (ilist.h:557).
  • Thread disposition: new.
  • Repair: Delegate glist_foreach to dlist_foreach(iter, glist_dhead(lhead)) where glist_dhead extracts the embedded dlist_head * for either head type, guaranteeing sentinel-terminated semantics. Repair validation: passed.

BLOCKER-C — glist_foreach_modify_next reads freed cur->next (use-after-free)

  • Location: src/include/lib/ilist.h:1265-1268
  • Class: correctness
  • Mechanism: glist_foreach_modify_next does cur = cur->next (raw, possibly freed) then next = cur->next, instead of cur = next; next = cur->next (saved) as canonical dlist_foreach_modify (ilist.h:647) does. The mutable iterator's saved next is never used for advancement.
  • Failure: When the loop body deletes/frees the current node (the documented-safe operation, ilist.h:106-112), glist_foreach_modify_next reads cur->next after cur is freed — a use-after-free.
  • Verification: verified (repro) — runtime trace: in a modify loop that deletes the current node and poisons its memory (mit.cur->next = 0xdeadbeef), the loop segfaulted (exit=139, SIGSEGV).
  • Thread disposition: new.
  • Repair: Delegate glist_foreach_modify to dlist_foreach_modify(iter, glist_dhead(lhead)), inheriting the saved-next advancement semantics. Repair validation: passed.

MAJOR-D — Count-contract conflation in glist_delete / glist_delete_thoroughly

  • Location: src/include/lib/ilist.h:1185-1192
  • Class: maintainability
  • Mechanism: glist_delete/glist_delete_thoroughly map to non-count-maintaining dlist_delete (dlist) vs count-maintaining dclist_delete_from (dclist), hiding the asymmetry the dlist/dclist split was designed to make explicit (ilist.h:13-23).
  • Failure: A caller cannot tell from the call site whether head->count is maintained. A naive "fix" aliasing dlist_delete for the dclist arm would silently desync the count.
  • Verification: verified (static-check) — inspection against the dlist/dclist count contract.
  • Thread disposition: new.
  • Repair: Route dclist arm to dclist_delete_from (count-maintaining); document the asymmetry in the header comment block. Repair validation: passed.

MAJOR-E — Expression-form _Generic evaluates all arms (arity/type errors)

  • Location: src/include/lib/ilist.h:1177-1192
  • Class: correctness
  • Mechanism: glist_insert_after/insert_before/delete/delete_thoroughly use the expression-form _Generic((head), T:(fn(args)), ...) with the call inside each association and no outer parentheses. C11 _Generic type-checks every association's expression even though only one is selected.
  • Failure: glist_insert_after(&dl, &a, &c) on a dlist_head * produces incompatible-pointer-type errors because the dclist association is type-checked against a dlist_head *.
  • Verification: verified (compile) — repro_blocker.c:58:28: error: passing argument 1 of 'dclist_insert_after' from incompatible pointer type.
  • Thread disposition: new.
  • Repair: Convert all macros to the function-form (_Generic((head), T: fn, ...)(args)) using head-accepting wrappers for arity-mismatched dlist primitives. Repair validation: passed.

MAJOR-F — glist_foreach* drop StaticAssertVariableIsOfTypeMacro type guards

  • Location: src/include/lib/ilist.h:1246-1273
  • Class: maintainability
