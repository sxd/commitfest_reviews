CommitFest 60 Patch 6999 — Add PROMPT_COMMAND and dynamic prompt support to psql

Author: Kirk Roybal <kirk.roybal@gmail.com> Verdict: waiting-on-author (3 verified BLOCKERs) Blocker split: verified=3, unverified=0 Head: 7cb9060dcde (uncommitted worktree diff, blob 5944340e) CommitFest: 60, Patch: 6999

Summary

This patch adds bash-like PROMPT_COMMAND support to psql: a shell command run before each interactive prompt, with its first-line stdout captured and insertable into PROMPT1/PROMPT2 via a new %D escape. A new SHELL_EXIT psql variable unifies the exit status of SQL and shell commands. An optional PROMPT_SESSION_EXPORT variable gates export of connection/session environment (PGDATABASE, PGUSER, PGHOST, PGPORT, PSQL_TXN, PSQL_SUPERUSER, PSQL_ROW_COUNT, PSQL_TXID, PSQL_SHELL_EXIT) into the PROMPT_COMMAND subprocess. A reset_prompt_status_after_connect() hook clears ROW_COUNT/SHELL_EXIT and optionally refreshes :txid after \connect. The get_prompt() function is rewritten from a fixed 256-byte static buffer to a heap PQExpBuffer with 8192-byte cap.

The feature concept has community precedent (Álvaro Herrera, 2016, thread 355228) but the execution has three blockers and several majors that must be addressed before committer pickup. The on-list review thread is thin (cover letter + one-line author reply only; no reviewer feedback yet).

Security review

No BLOCKERs. One MAJOR security finding (SEC-M1): PGUSER is set from session_username() which returns the SET ROLE target, not the login user. When PROMPT_SESSION_EXPORT is on, this leaks the elevated identity to child processes and persists in the parent process env, affecting subsequent \connect. Two MINOR security findings (SEC-m1, SEC-m2) are duplicates of F-004 and F-001 respectively.

Non-findings: command injection via PROMPT_COMMAND is consistent with existing %\...\` and \! shell facilities (same trust boundary, opt-in). No SQL injection (constant literal query). No credential exfiltration (PGPASSWORD` not exported).

Residual risk

The feature is opt-in and backward-compatible by default (all new variables inert until set). The main residual risks after repair are:

  1. The setenv env-mutation (F-005/SEC-M1) is a subtle correctness hazard that

the save/restore pattern addresses, but the pty test for PROMPT_SESSION_EXPORT is a new test pattern that should be validated on CI with IO::Pty available.

  1. The readline branch (input.c:88-95) is not exercised by the non-readline

coverage build; a readline-enabled CI run should verify the same run_prompt_command() call path.

  1. The thread has no reviewer feedback; the 2016 prior-art objections

(aborted-xact gating) should be surfaced to the author before committer pickup.
