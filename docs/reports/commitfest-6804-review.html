Wiki "Reviewing a Patch" six-heading summary

  1. What it does: Adds a SIGHUP GUC log_postmaster_stats (seconds, default 0=off). When positive, the postmaster periodically emits a LOG line with connection rate, disconnection rate, parallel-worker-start rate, and postmaster CPU/elapsed usage (pg_rusage_show). DetermineSleepTime caps wakeups to the configured interval.
  2. Does it work: Yes, mechanically. Compiles cleanly against HEAD; the logic is straightforward and consistent with existing periodic-block patterns in ServerLoop. No crash/assertion path found. Verified non-findings: lockless parallel_register_count read (PAT-6/SEC-1) and DetermineSleepTime cap (PAT-5) are correct.
  3. Performance: One getrusage + gettimeofday per interval (≥1s); negligible vs fork() cost. Unlocked shared-memory read is the established postmaster pattern. No hot-path cost when =0.
  4. Security: No new external input, no privilege change, no catalog access, getrusage(RUSAGE_SELF) is process-local. No security finding (SEC-1/SEC-4 refuted as security issues; SEC-2/SEC-5/SEC-6 informational non-findings).
  5. Smarter approaches: The unresolved idle-flood (PAT-2) is the main design smell; the author's own later thread direction (overload-oriented GUCs) and Robert Haas's M7 cumulative-stats/connection-rate proposal are competing, arguably smarter approaches. The simple periodic GUC and the overload GUCs should be reconciled on-list (PAT-1).
  6. Conclusion: Sound, low-risk implementation hampered by an open design/process question and a weak test. Address PAT-1 (thread confirm), PAT-2 (idle flood), PAT-3 (test strength), then ready-for-committer.
