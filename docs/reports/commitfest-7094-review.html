CommitFest 7094 Review — coerce_type string→unknown passthrough

Summary

The staged patch (10 lines, src/backend/parser/parse_coerce.c:415-422) adds a special case in coerce_type: when the target type is UNKNOWNOID and the input type's base category is TYPCATEGORY_STRING, return the node unchanged. This is the V1 approach proposed by Jian He on pgsql-hackers thread 635318 (2026-01-29), which Tom Lane explicitly objected to ("I certainly don't like the cast pathway you suggest adding to make it not be one — that seems likely to cause lots of not-very-desirable behaviors"). The author later moved to a V2 (2026-04-22) that disallows unknown targets in find_coercion_pathway instead. The staged patch is stale relative to thread consensus.

Verdict: waiting-on-author — 1 verified BLOCKER (F1: stale vs thread / live objection), 5 MAJOR findings, 1 coverage MAJOR (COV-1), 4 MINOR findings. The V2 repair (un-stage V1; add if (targetTypeId == UNKNOWNOID) return COERCION_PATH_NONE; in find_coercion_pathway) resolves all findings simultaneously and was validated by compile + full make installcheck (243/243 pass) + behavioral probes.
