CommitFest 7151 Review: Let OpenSSL auto-select DH parameters by default

Author: Peter Eisentraut <peter@eisentraut.org> Patch announcement: 2026-08-11, pgsql-hackers (Message-ID <953bceb7-340d-4717-9682-0ebe65c4b57e@eisentraut.org>) Verdict: ready-for-committer Scope: HEAD 1f2245371e3 (staged diff, 4 files, +39/-106)

Summary

The patch replaces the compiled-in FILE_DH2048 DH parameter constant with a call to SSL_CTX_set_dh_auto(context, 1), letting OpenSSL select well-known, appropriately-sized DH parameters consistent with the server certificate key size. The hardcoded 2048-bit RFC 3526 parameter block is removed from libpq-be.h, the load_dh_buffer() helper is deleted, the README.SSL Ephemeral DH section is removed, and config.sgml is updated to describe the new behavior and mark ssl_dh_params_file obsolescent. The initialize_dh() function is rewritten to use the custom file when set and OpenSSL auto selection otherwise.

A preflight disposable build with coverage instrumentation succeeded, the src/test/ssl TAP suite passed 450/450 tests (PG_TEST_EXTRA=ssl), and a manual ssl_dh_params_file-set server start plus TLS 1.2/1.3 connections succeeded.

CORR-2

(MINOR, correctness) — Reload-failure behavior change (REFUTED)

Location: src/backend/libpq/be-secure-openssl.c:2099 Status: refuted

The patch changes reload behavior: when ssl_dh_params_file is set but the file fails to load, initialize_dh() now returns false immediately (no fallback), causing the SSL reinitialization to fail and the server to retain the old SSL context — whereas the old code fell back to FILE_DH2048.

This is refuted as a defect: the patch author explicitly documented and justified this change in the pgsql-hackers announcement, calling the old fallback a bug because it silently masked a misconfiguration instead of failing the reload like every other SSL reinitialization error. The compiled- in fallback no longer exists by design. This is an intentional, thread- corroborated design decision.
