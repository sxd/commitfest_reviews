CommitFest 7577 — Review Report (v2)

Summary

The patch fixes a stale-hash-entry bug in ReleaseAuxProcessResources() in src/backend/utils/resowner/resowner.c. AuxProcessResourceOwner is the only resource owner that is *reused* after a full ResourceOwnerRelease cycle. ResourceOwnerSort() compacts every slot with kind != NULL into a contiguous prefix and qsorts it; ResourceOwnerReleaseAll() then walks that prefix from the end, decrementing nhash/narr without zeroing the released slots. After bulk release nhash == 0 yet hash[0..old_nhash) still hold released (item, kind) entries. On reuse, ResourceOwnerEnlarge() rehashes by scanning the full capacity and re-adds every slot where kind != NULL, re-inserting stale entries whose item Datums may point to already-released resources — a double-release / use-after-free when the reused owner is next released.

The fix adds, before resetting releasing/sorted:

c
if (AuxProcessResourceOwner->hash != NULL)
    memset(AuxProcessResourceOwner->hash, 0,
           AuxProcessResourceOwner->capacity * sizeof(ResourceElem));

This clears every slot to {0, NULL} (the documented free-slot sentinel), so reuse is safe. The fix is correct, minimal, and scoped to the only reuse site. A new test_resowner_aux regression test reproduces the bug via per-resource release counters and exercises both the array-only (16) and hash (64/65/1024) paths.

Verdict: ready-for-committer. 0 blockers, 0 majors. One MINOR test-gap finding (F9) with a concrete validated repair, plus optional NITs.
