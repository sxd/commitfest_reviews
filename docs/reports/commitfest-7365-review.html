CommitFest 7365 Review: Partial Indexes on System Catalogs

Verdict: needs-review

Blocker split: verified 0 / unverified 0. No blockers. One correctness MAJOR (misc_sanity test breakage, FIND-001) and one live-thread design objection MAJOR (FIND-002) drive the needs-review verdict per the deterministic rubric (correctness MAJOR + live objection => needs-review).

Patch Summary

This patch adds support for partial indexes on system catalogs with a restricted whitelist of predicate shapes that can be evaluated during catalog maintenance without building an EState:

  • oidcol <> k (OID inequality) — evaluated by direct slot_getattr comparison
  • col IS NOT NULL (NullTest) — evaluated by checking slot nullness

The patch modifies:

  • src/backend/bootstrap/bootparse.y — adds WHERE grammar production and makeBootCatalogPredicate() to hand-build the OpExpr predicate during bootstrap
  • src/backend/bootstrap/bootscanner.l — adds <> (NEQ) and WHERE tokens
  • src/backend/catalog/indexing.c — adds catalog_pred_clause_supported(), CheckCatalogIndexPredicate(), and CatalogIndexPredSatisfied(); integrates predicate evaluation into CatalogIndexInsert()
  • src/backend/commands/indexcmds.c — adds creation-time CheckCatalogIndexPredicate() call for catalog indexes
  • src/backend/catalog/genbki.pl — suppresses constraint generation for partial unique indexes
  • src/include/catalog/pg_constraint.h — declares 3 new partial indexes on pg_constraint (OIDs 580, 581, 582)
  • src/test/regress/ — adds catalog_partial_index regression test

Findings

FIND-001

— MAJOR (correctness): misc_sanity regression test breaks

Location: src/test/regress/expected/misc_sanity.out:97

Mechanism: The patch adds two new unique partial indexes on pg_constraint (pg_constraint_conrelid_conname_index OID 581, pg_constraint_contypid_conname_index OID 582). genbki.pl correctly suppresses pg_constraint constraint generation for partial unique indexes (the WHERE regex check at line 155), so these indexes have no backing pg_constraint entry. However, the existing misc_sanity regression test asserts that no system catalog unique index lacks a backing constraint ("There should be none"). The test's expected output was not updated.

Verification: verified by reproduction. Full make installcheck with an instrumented build: "1 of 240 tests failed" — misc_sanity.out.diff shows the 2 new unique partial indexes. Confirmed via SQL that both indexes have indisunique=true and no pg_constraint row with matching conindid. Applied the repair (updating expected output) to a scratch copy and re-ran misc_sanity: "All 1 tests passed."

Repair: Update src/test/regress/expected/misc_sanity.out to list the 2 new unique partial indexes as expected results. The test comment "(There should be none.)" should be updated to reflect that partial unique indexes intentionally lack backing constraints.

Repair validation: passed (apply-check + diff-check + targeted-test). The repair patch applies cleanly to HEAD; re-running misc_sanity with the updated expected output passes.

FIND-002

— MAJOR (correctness, cannot-verify): Live thread design objection

Location: src/backend/catalog/indexing.c:77 (overall design)

Mechanism: The patch's design approach is contested by two senior reviewers on pgsql-hackers thread 657827:

  • Tom Lane (2026-10-01): skeptical of the restricted whitelist — "we don't have partial indexes, just a hack with a small number of potential use-cases." Suggests pg_constraint is misdesigned and should be refactored via breakout catalogs instead.
  • Andres Freund (2026-10-01): questions whether the gain warrants the complexity, noting catcache negative-lookup caching may negate the benefit. Requests an actual benefiting index + syscache.

The patch author labels it "meant for experimentation, not for commit."

Verification: cannot-verify (design-acceptability objection, not a code defect). The thread is live with no resolution.

Repair: No code repair — this requires author response on pgsql-hackers addressing both reviewers' concerns, or a revised approach.

COV-001

— MINOR (tests): Uncovered NullTest IS NOT NULL false-return path

Location: src/backend/catalog/indexing.c:164

Mechanism: Changed-code coverage identified an uncovered executable line: the NullTest IS NOT NULL false-return path in CatalogIndexPredSatisfied. When a partial catalog index has a column IS NOT NULL predicate and a catalog row is inserted where that column is NULL, line 164 (return false) should execute. The existing test only creates a contypid IS NOT NULL index on a NOT NULL column, so isnull is always false.

Verification: verified by coverage. gcov branch data for line 163 shows branch 0 (isnull true) taken 0%. Confirmed that pg_constraint.conbin is nullable and PK/UNIQUE/NOT NULL constraints have conbin=NULL. A test creating a conbin IS NOT NULL partial index + a PK table insert exercises this path.

Repair: Add a test section to catalog_partial_index.sql that creates a conbin IS NOT NULL partial index and creates a table with a PRIMARY KEY (inserting a pg_constraint row with conbin=NULL).

Repair validation: partial. Manual SQL execution confirmed the path is exercised; full pg_regress expected-output integration pending.
