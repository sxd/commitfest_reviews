Patch Summary

The patch makes functional-dependency extended statistics applicable when costing parameterized base-relation paths. Previously, clauselist_selectivity_ext only applied extended stats when all clauses referenced a single relation (find_single_rel_for_clauses returned non-NULL). For a parameterized scan, clauses include join quals like t1.a = t2.b, so find_single_rel_for_clauses returns NULL and no extended stats were used — even though varRelid identifies the scanned relation.

Two coordinated changes:

  1. src/backend/optimizer/path/clausesel.c:158-166 — when

use_extended_stats && rel == NULL && varRelid != 0, look up paramrel = find_base_rel(root, varRelid) and, if it is an RTE_RELATION with stats, call dependencies_clauselist_selectivity on it, multiplying the result into s1.

  1. src/backend/statistics/dependencies.c:743-788 —

dependency_is_compatible_clause now allows up to two varnos (was BMS_SINGLETON), and in the OpExpr branch, when neither arg is pseudoconstant, accepts Var(relid) = Var(other-single-rel) and treats the other relation's Var as a pseudoconstant.

Runtime Verification

Built PostgreSQL with meson+ninja in a disposable scratch build with coverage instrumentation (b_coverage=true). Ran the author's repro and additional scenarios against a scratch PostgreSQL instance:

  • Without stats: rows=2 per probe (independence assumption: 1/1000 × 1/100)
  • With dependency stats: rows=200 per probe (matching actual 200 rows/probe)
  • LEFT JOIN: also benefits (rows=200 with stats)
  • 3-way joins with outer joins: no crash, correct estimates
  • Plan change: Index Scan → Bitmap Heap Scan due to improved cost estimate

No crash observed in any tested scenario (inner join, LEFT JOIN, RIGHT JOIN, FULL JOIN, 3-way joins with outer joins, OR clauses).

Findings

F-1

— MAJOR (tests): No test coverage for the new behavior

Location: src/test/regress/sql/stats_ext.sql (absence) Class: tests Verification: verified (code inspection + runtime testing)

The patch changes planner estimates for parameterized paths but adds no regression tests. Existing stats_ext.sql covers functional dependencies only for single-relation WHERE restrictions. Without tests, a future refactor could silently revert the behavior.

Repair: Append a test section to stats_ext.sql that creates correlated columns with functional dependency statistics, forces a parameterized nested loop join, and verifies the per-probe row estimate changes. Test patch validated by applying to scratch source, rebuilding, and confirming rows=1 without stats → rows=10 with stats on the inner Index Scan.

Test example (regress):

sql
CREATE TABLE dep_param_t1 (a int, b int, c int) WITH (autovacuum_enabled = off);
CREATE TABLE dep_param_t2 (a int, b int) WITH (autovacuum_enabled = off);
INSERT INTO dep_param_t1 SELECT i%100, i%100, i%100 FROM generate_series(1,1000) i;
INSERT INTO dep_param_t2 SELECT i, i FROM generate_series(0,99) i;
CREATE INDEX dep_param_t1_a_b_idx ON dep_param_t1 (a, b);
ANALYZE dep_param_t1, dep_param_t2;
SET enable_hashjoin = off; SET enable_mergejoin = off; SET enable_bitmapscan = off;
EXPLAIN (COSTS ON)
SELECT * FROM dep_param_t2, dep_param_t1
WHERE dep_param_t1.a = dep_param_t2.a AND dep_param_t1.b = dep_param_t2.b;
CREATE STATISTICS dep_param_st (dependencies) ON a, b FROM dep_param_t1;
ANALYZE dep_param_t1;
EXPLAIN (COSTS ON)
SELECT * FROM dep_param_t2, dep_param_t1
WHERE dep_param_t1.a = dep_param_t2.a AND dep_param_t1.b = dep_param_t2.b;

Oracle: rows=1 without stats → rows=10 with stats on inner Index Scan.

F-2

— MINOR (correctness): find_base_rel can ERROR on unexpected varRelid

Location: src/backend/optimizer/path/clausesel.c:160 Class: correctness Verification: verified (code inspection + runtime testing)

find_base_rel(root, varRelid) calls elog(ERROR) if the slot is NULL or out of range. All current callers pass valid base-rel varRelids, so no crash is reachable today. Using find_base_rel_noerr + NULL check is a low-cost defensive improvement.

Repair:

c
RelOptInfo *paramrel = find_base_rel_noerr(root, varRelid);
if (paramrel && paramrel->rtekind == RTE_RELATION && paramrel->statlist != NIL)

Validated: applied to scratch source, rebuilt, ran join tests — no regression.

F-3

— MINOR (maintainability): Bitmapset leak — largrelids/rargrelids not freed

Location: src/backend/statistics/dependencies.c:773-774 Class: maintainability Verification: verified (code inspection)

The new pull_varnos results are never bms_free'd. Planner context resets per-query, but this is inconsistent with PostgreSQL's bitmapset hygiene.

Repair: Add bms_free(largrelids); bms_free(rargrelids); before all exit paths. Validated: applied, rebuilt, no regression.

F-4

— MINOR (correctness): Outer-join/nullingrels scope limitation

Location: src/backend/statistics/dependencies.c:743, 773-784 Class: correctness Verification: cannot-verify (scope limitation, not a code defect)

pull_varnos includes varnullingrels, which could cause BMS_SINGLETON tests to fail for outer-join-nullled Vars. However, runtime testing showed the patch works for LEFT JOIN parameterized scans because EC-generated clauses use plain Vars without nulling relids. This is a scope limitation, not a bug. No repair needed for current scope; should be addressed if the caller surface expands to pass nullled Var clauses.

F-5

— MINOR (docs): No documentation update

Location: doc/src/sgml/planstats.sgml:458 Class: docs Verification: cannot-verify (documentation change)

The Functional Dependencies docs don't mention the new parameterized-path application. A short paragraph should be added noting that dependency statistics are also applied when costing parameterized scan paths.

F-7

— MINOR (maintainability): pull_varnos(NULL,...) PHV handling — REFUTED

Residual Risk

  • The patch treats the join-partner Var as a pseudoconstant, averaging over

its value distribution. This is a sound first-order approximation but may be less accurate for highly skewed join keys. The author acknowledges this and plans MCV/ndistinct as follow-up work.

  • The scan-vs-join estimate inconsistency noted by Vondra (50 × 200 ≠ 98) is

not resolved by this patch and remains an open item for join-level estimation follow-up.

  • The right-arg-is-relid path (lines 781-785) is unreachable through normal SQL

due to EC clause Var ordering normalization. This is defensive code that is correct but untestable through regression tests.
