CF6967 Review — Add malloc attribute to memory allocation functions

Patch: "Add malloc attribute to memory allocation functions" (Tristan Partin) CommitFest: 61, Patch 6967 Canonical Message-ID: DJNFBUWD276K.2OPIYJQS75W84@partin.io Thread: pgsql-hackers thread 650381 (2026-07-01 to 2026-07-07, 11 messages) Target: uncommitted working-tree diff (read-only worktree) HEAD/base: 7cb9060dcde08ca63df1f0d701b0674e0e8ae811 Diff SHA (sha256): 067e961369b52100ecf6bf8101a3a7e2b6c5426ff6662d21b02f330fb91f363b Changed files (3): src/include/c.h (+12/-0), src/include/common/fe_memutils.h (+18/-18), src/include/utils/palloc.h (+18/-18)

Verdict

PostgreSQL verdict: waiting-on-author

Blocker split: verified=1, unverified=0

The patch has a verified BLOCKER: the pgsql-hackers thread consensus (led by senior committer Tom Lane) opposes annotating backend allocators because GCC's -analyzer cannot understand memory-context-based lifecycles, producing massive false-positive leak warnings (62→598). The author acknowledges the backend portion "may not be committed." The patch as submitted annotates both frontend AND backend allocators, contradicting this consensus.

The author should split the patch: submit the frontend-only annotations (fe_memutils.h) as the primary patch, and either drop the backend annotations (palloc.h) or submit them separately as exploratory. Additionally, fix the GCC version guard to require __GNUC__ >= 11 for the deallocator-argument form.

F2

[MAJOR] — Deallocator-attribute semantic mismatch on backend allocators

Class: correctness Location: src/include/utils/palloc.h:79-82,93-95,157-164 Mechanism: deallocator-attribute-semantic-mismatch

Description: pg_attribute_malloc(pfree) on backend allocators asserts a deallocator contract that most call sites do not honour. Backend memory is typically freed by MemoryContextReset/MemoryContextDelete (bulk context teardown), not individual pfree() calls. GCC cannot see context resets as freeing the chunk, producing 536 new false-positive -Wanalyzer-malloc-leak warnings (62→598).

Verification: verified (inspection) Evidence: src/include/utils/palloc.h lines 79-82, 93-95, 157-164 show pg_attribute_malloc(pfree) on backend allocators. src/backend/utils/mmgr/aset.c:546: AllocSetReset frees all chunks without pfree. src/include/utils/memutils.h:74-78: MemoryContextReset/Delete are primary deallocation mechanisms. Thread evidence: author measured 62→598 warnings.

Repair: Same as F1 — revert palloc.h to HEAD. The false-positive deallocator contract is eliminated.

Validation: passed (apply-check, diff-check, compile, static-check).

F3

[MAJOR] — GCC < 11 guard too broad for deallocator-argument form

Class: correctness Location: src/include/c.h:283-287 Mechanism: compiler-version-guard-too-broad

Description: __has_attribute(malloc) returns true on GCC 5-10, but the deallocator-argument form malloc(dealloc) was only added in GCC 11. On older GCC, pg_attribute_malloc(pfree) expands to __attribute__((malloc(pfree))) which is silently ignored with a -Wattributes warning. With -Werror, this would be a build failure.

Verification: verified (inspection) Evidence: src/include/c.h:283: #if __has_attribute(malloc) && !defined(__clang__). GCC manual: malloc(deallocator) form added in GCC 11. __has_attribute(malloc) returns true on GCC 5+.

Repair:

  • Instruction: Change guard to #if __has_attribute(malloc) && !defined(__clang__) && __GNUC__ >= 11. Update comment to document GCC 11 requirement.
  • Code example (exact-postimage): #if __has_attribute(malloc) && !defined(__clang__) && __GNUC__ >= 11
  • Patch: Included in the combined repair patch (SHA-256 5caef3148dc00dada1630eb9b2cd008b702405b8313b82e2c9db375f40342420).
  • Validation: passed (apply-check, diff-check, compile, static-check). All affected targets compiled successfully on GCC 15.2.0.
  • Test example: Inspection: grep '__GNUC__ >= 11' src/include/c.h confirms guard is present.
