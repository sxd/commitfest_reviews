CommitFest 7254 — Review Report

Allow bare library names for non-superuser LOAD

Patch summary

This patch moves the $libdir/plugins/ bare-library-name auto-expansion from load_libraries() (src/backend/utils/init/miscinit.c) into load_file() (src/backend/utils/fmgr/dfmgr.c), so that the SQL LOAD command for non-superusers (utility.c:854, restricted = !superuser()) gains the same bare-name convenience that local_preload_libraries already had. After the patch, a non-superuser can write LOAD 'mylib'; and have it interpreted as LOAD '$libdir/plugins/mylib';. The security model is preserved: the expansion only fires for names with no directory separator, and the expanded result is still validated by check_restricted_library_name().

Three files changed (+19/-15): doc/src/sgml/ref/load.sgml (documentation update), src/backend/utils/fmgr/dfmgr.c (expansion moved here), src/backend/utils/init/miscinit.c (expansion removed here).

SEC-1

— MAJOR / security — refuted (pre-existing, not widened)

Location: src/backend/utils/fmgr/dfmgr.c:159-166 + check_restricted_library_name at dfmgr.c:533-542

Mechanism: check_restricted_library_name passes tails that are exactly . or .. (no separator in the tail), so LOAD '..' / LOAD '$libdir/plugins/..' both reach expand_dynamic_library_name as $libdir/plugins/.. which resolves to a directory; dlopen/stat on the unexpanded literal $libdir path fails.

Why refuted: This behavior is pre-existing — LOAD '$libdir/plugins/..' was already accepted pre-patch (the check is unchanged by the CF diff), and the traversal is fully blocked downstream by pg_file_exists (rejects directories) and stat on the unexpanded literal $libdir path. The set of loadable regular-file targets remains exactly $libdir/plugins/<file>. This patch does not widen the attack surface; it only adds a second syntactic route (LOAD '..') to the same already-dead- ended traversal.

Follow-up note (not a finding against this patch): As a defense-in-depth improvement independent of this patch, check_restricted_library_name could be hardened to reject all-dots tails (strspn(tail, ".") == strlen(tail)) so the documented invariant holds even if downstream dlopen/stat behavior ever changes. Suggested for a separate hardening commit.
